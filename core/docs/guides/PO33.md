# Work with PO-33 / PO-133 backups

[Build and capture setup](../../examples/README.md) · [Documentation](../README.md)

Run commands from the repository root after building the tools. See the
[capture requirements](../../examples/README.md#capture-input) before decoding.

## PO-33 / PO-133 Decode and Re-encode

```sh
./build/core/po33_decode_capture backup.wav decoded-po33
./build/core/po33_encode_capture decoded-po33/frame.bin rebuilt-po33.wav
./build/core/po33_decode_capture rebuilt-po33.wav checked-po33
cmp decoded-po33/frame.bin checked-po33/frame.bin
```

PO-33 uses the input channels in their supplied order. Alongside the raw frame
and packets, the decoder writes `settings.bin`, `pattern-NN.bin` and
`sound-NNN.bin`. A populated sample pool also gets a WAV. The sound binary keeps
its nine-byte header and all allocated sample bytes; the WAV expands the entire
pool to PCM16 at 23,438 Hz, the nearest integer to the nominal 23,437.5 Hz clock.

The WAV is not necessarily the portion a slot plays: the decoder does not apply
trim or slice references. Multiple slots or slices can refer to one pool, even
to audio outside the owning sound's trim. Raw endpoints can overlap or exceed
an allocation; whether playback includes each endpoint remains unresolved.

Both stereo encoders default to 48 kHz. Use `--rate 44100`, `--rate 48000` or
`--rate 96000` to change the transfer WAV rate; this does not change the sample
clock or speech frame rate. Re-encoding without edits preserves the decoded
frame bytes, not the original recorded waveform. The final `cmp` checks that
the rebuilt transfer decodes to the same frame in software.

## Inspect pool topology before editing

```sh
./build/core/po33_pool_manifest decoded-po33/frame.bin
```

The manifest exposes owned pools and resolved references without interpreting
raw trim/slice coordinates. A shared resolved pool can be structurally
referenced by multiple records; that does not establish every audible effect
of replacement. Header-only records and selectors with no following
`SOUND_DATA` packet are distinct: the latter have no topology record.

## PO-33 / PO-133 Template Editing

Start from a decoded backup whose sample pool already exists. The replacement
must be a nonempty PCM16, PCM24, PCM32 or float32 WAV at 8–192 kHz, including
extensible WAV; samples must be finite and in `[-1,1]`. The converter targets
the nominal 23,437.5 Hz clock and treats exported 23,438 Hz WAVs as native-rate
input.

The index selects a stored pool, not an independent copy of every sound that
uses it. Replacing a shared pool can therefore affect several slots or slices.
A drum group can also contain more than one pool, so inspect the topology
manifest before deciding which pool to replace.

Applications using the C API can build the caller-owned pool topology and call
`po33_pool_replacement_plan` before any edit. The planner takes an owned
sound-record index plus the requested encoded sample-byte count. It reports the
retained or block-rounded allocation, resolved reference count and structural
growth readiness, while rejecting header-only targets, selector ambiguity,
unknown target-group extensions and unsafe growth shapes. It does not convert
audio, alter a frame, detach aliases, extend trims, reclaim storage or establish
device capacity; see the [PO-33 C API](../api/PO33.md#conservative-pool-replacement-planning).

Freestanding applications that already have encoded mu-law sample bytes can
instead call `po33_pool_edit_plan` and `po33_pool_edit_rebuild`. The target is
the manifest's sound-record index, not a selector. Those functions preserve the
existing header and raw references, stage a complete rebuilt frame in
caller-owned memory and do not make a hardware-capacity claim; see
[transactional encoded pool replacement](../api/PO33.md#transactional-encoded-pool-replacement).

```sh
./build/core/po33_encode_capture decoded-po33/frame.bin edited-po33.wav \
  --sample 0 edited-sound-000.wav \
  --pattern 0 edited-pattern-00.bin
```

Mono input needs no channel option. Stereo requires an explicit global channel
choice; `left` and `right` select one channel, and `mix` takes their arithmetic
mean. Mono accepts `left` or `mix` and rejects `right`.

```sh
./build/core/po33_encode_capture decoded-po33/frame.bin edited-po33.wav \
  --sample 0 new-stereo-recording.wav --channel mix
```

Shorter audio is padded with silence to the existing allocation. Longer audio
grows the pool in 4,096-byte blocks, with silence in the final partial block;
it is never truncated to fit the old length. Growth requires a block-aligned
original pool and rejects ambiguous extensions in the selected sound group.
The editor preserves trim coordinates and slice references exactly. It does
not extend trims to cover appended audio or reclaim storage after a shorter
replacement. Device storage capacity and restoration of larger pools remain
unverified.

Selectors are zero-based and match the exported filenames. Pattern replacements
are raw records of the original length; keep parameter-only rows even when the
control byte is zero. Their observed roles do not establish exact numeric
scales; see [PO-33 format reference](../formats/PO33.md). To replace one raw pattern
byte instead of the whole record:

```sh
./build/core/po33_encode_capture decoded-po33/frame.bin edited-pattern.wav \
  --pattern-byte 0 768 252
```

This changes a raw byte; it is not a musical-note editing API. Options can be
repeated for different records, and conflicting edits are rejected. The editor
preserves settings, patterns not explicitly edited, all sample headers and
unselected content. Existing packet lengths and order are retained; growth adds
sample-data packets to the selected group. It cannot create a new pool from a
missing or metadata-only entry, change trim endpoints or remap slices. Edited
PCM is quantized to the nearest representable mu-law level. Unchanged native
PCM retains its original byte, including the alternate zero encoding. Input is
not gain-normalized; overshoot from sample-rate conversion is saturated before
quantization. Outputs must not exist, and all edits validate before creation.
