# PO-33 / PO-133 C API

[API overview](../C_API.md) · [Documentation](../README.md)

See [ownership and completion](../C_API.md#data-flow-and-ownership) before integrating these APIs.
Use the [shared stereo APIs](STEREO.md) to parse, build and transmit a frame.

## PO-33 Records and Samples

`po33_settings_*`, `po33_pattern_*` and `po33_sound_header_*` encode and decode
fixed-size logical records. A logical record can span several wire packets;
the application collects those payloads before calling the record codec.
Unknown fields, unused chain entries and raw sample ranges are preserved.
Input and output storage must not overlap.

For these fixed records, null input/output is `PO_ERR_INVALID_ARG`, an incorrect
decode length is `PO_ERR_FRAME`, and insufficient encode capacity is
`PO_ERR_BUFFER_TOO_SMALL`. Settings accept chain lengths 0..128 and reject
larger values with `PO_ERR_RANGE`. Failed operations leave outputs unchanged;
successful encoders leave excess output capacity untouched. These are the
existing PO-33 contracts; PO-35's fixed-record length error remains `PO_ERR_PARSE`.

The in-memory record and field views are:

| Type | Fields represented |
| --- | --- |
| `po33_settings_t` | Pattern chain, tempo, swing and retained raw state |
| `po33_pattern_t` | Sixteen steps by sixteen sounds, plus packed FX data |
| `po33_pattern_event_t` | Raw three-byte parameter word and control byte |
| `po33_pattern_control_t` | Separate `note_raw` and `timing_raw` nibbles |
| `po33_pattern_fx_t` | Sixteen unpacked per-step `code_raw` values |
| `po33_sound_header_t` | Raw range endpoints and source selector |

These structs are not wire overlays. Use the codecs rather than casting or
copying struct memory: pattern fields occupy separate serialized planes, and
native struct padding need not match record sizes.

## Pool Topology Views

`po33_pool_topology_requirements(frame, frame_len, &records, &pools, &references)`
validates a complete PO-33 frame and measures the caller-owned arrays needed
for its pool topology. It does not allocate storage, alter the source frame or
assign playback meaning to a raw range. All three count pointers are required.
On success they contain exact element counts; on failure they remain unchanged.
Null arguments return `PO_ERR_INVALID_ARG`, a malformed or incomplete source
frame or sound record returns `PO_ERR_FRAME`, and an unrepresentable count
returns `PO_ERR_RANGE`.

The three count outputs must be pairwise disjoint and disjoint from the source
frame. An overlap returns `PO_ERR_INVALID_ARG` before any count is written.

After allocating those three arrays, call
`po33_pool_topology_build(frame, frame_len, records, record_capacity, pools,
pool_capacity, references, reference_capacity)`. Each capacity must cover the
corresponding queried count. An array may be null only if its queried count is
zero and its supplied capacity is zero; null required storage returns
`PO_ERR_INVALID_ARG`, while short storage returns `PO_ERR_BUFFER_TOO_SMALL`.
The output arrays must be mutually disjoint and disjoint from the source frame;
an overlap returns `PO_ERR_INVALID_ARG` before writing. The build validates
before writing, so every supplied array remains unchanged on failure. On
success it writes exactly the queried elements and leaves
capacity beyond them untouched. It returns
`PO_ERR_FRAME` for malformed source records and `PO_ERR_RANGE` for an
unrepresentable count.

The caller-owned topology uses these views:

| Type | Meaning |
| --- | --- |
| `po33_frame_span_t` | Raw byte range in the complete source frame, including the preamble in its offset |
| `po33_sound_record_t` | One `SOUND_SELECT` record, its decoded raw header and its selection/data spans |
| `po33_pool_t` | An owned record with bytes after its nine-byte header |
| `po33_pool_reference_t` | A reverse relationship from an owned pool to a sound record whose source selector resolves to it |

`selection_span` covers the complete selector packet. `data_span` begins at
the first following `SOUND_DATA` packet and ends after the last one before the
next selector or END. It is a raw wire span: it includes packet headers,
trailers and any intervening unknown extension packets, so it is not a pointer
to one contiguous payload. A selector with no following `SOUND_DATA` packet is
an omitted sound and has no topology record. `po33_pool_t.data_bytes` instead counts only
`SOUND_DATA` payload bytes, including the nine-byte header. A zero-length span
has an offset of zero.

The header in `po33_sound_record_t` is a decoded copy of the first nine
`SOUND_DATA` payload bytes. Its `range_start_raw`, `range_end_raw` and
`source_selector` remain raw observations. No endpoint convention, playback
slice or allocation claim follows from them. Records with exactly the header
and no later sound-data bytes set `PO33_SOUND_RECORD_FLAG_HEADER_ONLY`; they
are references rather than owned pools. An owned record has an
`owned_pool_index`; a record whose source selector resolves to exactly one
owned pool has a `referenced_pool_index` and one reverse-reference entry.
Unavailable relationships use `SIZE_MAX`.

Topology deliberately retains ambiguity instead of collapsing it:

- `PO33_SOUND_RECORD_FLAG_DUPLICATE_SELECTOR` marks every record sharing a
  selector with another record.
- `PO33_SOUND_RECORD_FLAG_UNKNOWN_EXTENSION` marks a non-`SOUND_DATA` packet
  between a selector and its next selector or END.
- `PO33_SOUND_RECORD_FLAG_SOURCE_UNRESOLVED` means no owned pool has the raw
  source selector; `PO33_SOUND_RECORD_FLAG_SOURCE_AMBIGUOUS` means more than
  one candidate owner does.

Such facts do not make the requirements query succeed by guessing. They remain
in the views so an editor can reject or explain an unsafe change.
The requirements counts include every structurally complete sound record and
owned pool, while reverse-reference count includes only source selectors with
one unambiguous owned-pool target.

## Conservative Pool Replacement Planning

`po33_pool_replacement_plan(records, record_count, pools, pool_count,
target_record, requested_sample_bytes, &plan)` evaluates one owned pool without
changing a frame. The record and pool arrays must be the matching views returned
by `po33_pool_topology_build`; `target_record` is the owning sound-record index,
not a selector value or a pool index. This deliberately lets the planner reject
a header-only or otherwise nonowned target instead of guessing an owner.

`requested_sample_bytes` is the already encoded sample body, excluding the
nine-byte sound header. The plan reports the current body allocation, the
allocation that would be retained or required, and the added allocation. A
shorter request retains the old allocation; a longer request rounds up to
`PO33_POOL_ALLOCATION_BLOCK_BYTES` (4,096 bytes). It reports whether the old
allocation fits and whether a requested block growth is structurally eligible.
It does not parse WAV/PCM, produce an output frame, fill silence, allocate
memory, rewrite a packet, or state a device capacity.

`reference_count` is the exact count of topology records whose resolved
`referenced_pool_index` equals `target_pool_index`, including the owner if its
raw source selector resolves to itself. `affected_sound_record_count` counts
that owner once plus every other resolved reference. To show the exact selector
set, filter the caller-owned record view by that pool index; the reverse-reference
array from `po33_pool_topology_build` carries the same record indices. Once an
owned target pool is resolved, those counts remain complete even if the plan is
rejected for an unsafe boundary, allocation overflow, extension, or selector
relationship.

The plan is only successful when its reason is
`PO33_POOL_REPLACEMENT_REASON_NONE`. A header-only/nonowned or out-of-range
target returns `PO_ERR_RANGE`; malformed or ambiguous topology returns
`PO_ERR_PARSE`. The reason distinguishes duplicate or ambiguous selectors, an
unknown extension in the target group, ambiguous group boundaries, an unaligned
existing allocation for requested growth, and arithmetic overflow. An existing
allocation that is not block-aligned still permits a replacement that fits
without growth. An unresolved raw source selector does not turn a known owned
pool into a playback claim; raw source and range values remain unmodified.

The function needs no heap or scratch storage. It only reads the supplied
topology and writes the plan; inputs and plan storage must not overlap. An
overlapping plan is rejected with `PO_ERR_INVALID_ARG` before any plan write;
output guarantees do not apply to this invalid alias. An unrepresentable
input-array count also returns `PO_ERR_INVALID_ARG` without writing plan
storage, because the complete alias extent cannot be represented. Even a successful
structural plan is not a rebuild contract and does not prove that a larger pool
can be accepted or restored by PO-33/PO-133 hardware.

`po33_pattern_control_decode` splits a control byte into its low note/key nibble
and high timing nibble. `po33_pattern_control_encode` recombines them. Each raw
value is in 0..15; musical key numbering and timing units are not implied.
Held-step melodic length edits and drum retrigger edits share this high-nibble
location in different sound contexts. The zero control byte does not make a
nonzero parameter word disposable.

`po33_pattern_fx_decode` expands `PO33_PATTERN_FX_BYTES` packed bytes into one
code per step, high nibble first. `po33_pattern_fx_encode` packs them again.
`PO33_FX_OCTAVE_UP` names verified code 6; `PO33_FX_BASELINE` names the observed
normal baseline code 15 without claiming an explicit FX-clear operation.
Every code in 0..15 is preserved, including codes without a verified musical
name. Encoders reject out-of-range values before changing any output.

For example, edit the first step of an already decoded pattern while preserving
the other FX codes and all note/parameter fields:

```c
po_status_t set_first_step_octave_up(po33_pattern_t *pattern) {
  po33_pattern_fx_t fx;
  po_status_t status;
  if (pattern == NULL)
    return PO_ERR_INVALID_ARG;
  status = po33_pattern_fx_decode(pattern->footer_raw,
                                  sizeof(pattern->footer_raw), &fx);
  if (status != PO_OK)
    return status;
  fx.code_raw[0] = PO33_FX_OCTAVE_UP;
  return po33_pattern_fx_encode(&fx, pattern->footer_raw,
                                sizeof(pattern->footer_raw));
}
```

Then use `po33_pattern_encode` to serialize the edited logical record. The
existing packed fields remain available; the new views do not alter struct
layout or require allocation.

Pattern event words remain raw. In the descriptive q0–q3 partition, q0 has an
observed pitch role and q1 an observed level role; q2 controls a filter-like
response, with cutoff a strong inference. q3's resonance interpretation remains
an unconfirmed candidate. Exact scales, field widths, zero/sentinel behavior
and playback state carry are unresolved. Preserve parameter-only rows with
zero control bytes. See [PO-33 format reference](../formats/PO33.md) for the field map and
the distinction between observed behavior and candidate meanings.

`po33_sample_decode` expands one signed-order mu-law byte to PCM16.
`po33_sample_encode` selects the nearest representable level, with ties toward
zero. The nominal sample clock is 23,437.5 Hz. Headers and full allocated pools
must be handled by the application; the sample codec does not apply trims or
resolve slice references. Resolve a source selector against the whole stored
pool, not its owner's trimmed interval. Raw range endpoints can overlap or
exceed an allocation; endpoint inclusion and the cause of those anomalous
ranges remain unresolved. Do not clamp, wrap or rescale them on decode.

`po33_sample_count_for_pcm(count, rate, &required)` sizes a bulk conversion from
finite normalized mono PCM at 8,000–192,000 Hz. Except for the native WAV alias
23,438 Hz, the output count is `ceil(count * 46875 / (2 * rate))`, targeting the
nominal 23,437.5 Hz clock. The alias keeps the input count unchanged.

`po33_samples_encode_f32(pcm, count, rate, output, capacity, &written)` performs
bandlimited sample-rate conversion and emits one mu-law byte per output sample.
For example, one second at 48 kHz needs 23,438 output bytes. Input samples must
be finite and in `[-1,1]`; invalid samples are rejected before any output writes.
Resampling overshoot is saturated before PCM quantization. No input gain
normalization is performed.

Both functions set their output count to zero on error. Empty input produces
zero samples; input and output buffers may be null when their required lengths
are zero. Buffers and count storage must not overlap. The caller supplies memory;
there is no heap allocation, libc or libm dependency. The bulk API creates only
sample bytes, leaving block padding, headers and template edits to the caller.
