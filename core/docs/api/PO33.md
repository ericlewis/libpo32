## PO-33 Records and Samples

`po33_settings_*`, `po33_pattern_*` and `po33_sound_header_*` encode and decode
fixed-size logical records. A logical record can span several wire packets;
the application collects those payloads before calling the record codec.
Unknown fields, unused chain entries and raw sample ranges are preserved.
Input and output storage must not overlap.

For these fixed records, null input/output is `PO_ERR_INVALID_ARG`, an incorrect
decode length is `PO_ERR_FRAME`, and insufficient encode capacity is
`PO_ERR_BUFFER_TOO_SMALL`. Settings accept chain lengths 0..128 and reject
larger values with `PO_ERR_RANGE`. Failed operations leave outputs unchanged;
successful encoders leave excess output capacity untouched. These are the
existing PO-33 contracts; PO-35's fixed-record length error remains `PO_ERR_PARSE`.

The in-memory record and field views are:

| Type | Fields represented |
| --- | --- |
| `po33_settings_t` | Pattern chain, tempo, swing and retained raw state |
| `po33_pattern_t` | Sixteen steps by sixteen sounds, plus packed FX data |
| `po33_pattern_event_t` | Raw three-byte parameter word and control byte |
| `po33_pattern_control_t` | Separate `note_raw` and `timing_raw` nibbles |
| `po33_pattern_fx_t` | Sixteen unpacked per-step `code_raw` values |
| `po33_sound_header_t` | Raw range endpoints and source selector |

These structs are not wire overlays. Use the codecs rather than casting or
copying struct memory: pattern fields occupy separate serialized planes, and
native struct padding need not match record sizes.

`po33_pattern_control_decode` splits a control byte into its low note/key nibble
and high timing nibble. `po33_pattern_control_encode` recombines them. Each raw
value is in 0..15; musical key numbering and timing units are not implied.
Held-step melodic length edits and drum retrigger edits share this high-nibble
location in different sound contexts. The zero control byte does not make a
nonzero parameter word disposable.

`po33_pattern_fx_decode` expands `PO33_PATTERN_FX_BYTES` packed bytes into one
code per step, high nibble first. `po33_pattern_fx_encode` packs them again.
`PO33_FX_OCTAVE_UP` names verified code 6; `PO33_FX_BASELINE` names the observed
normal baseline code 15 without claiming an explicit FX-clear operation.
Every code in 0..15 is preserved, including codes without a verified musical
name. Encoders reject out-of-range values before changing any output.

For example, edit the first step of an already decoded pattern while preserving
the other FX codes and all note/parameter fields:

```c
po_status_t set_first_step_octave_up(po33_pattern_t *pattern) {
  po33_pattern_fx_t fx;
  po_status_t status;
  if (pattern == NULL)
    return PO_ERR_INVALID_ARG;
  status = po33_pattern_fx_decode(pattern->footer_raw,
                                  sizeof(pattern->footer_raw), &fx);
  if (status != PO_OK)
    return status;
  fx.code_raw[0] = PO33_FX_OCTAVE_UP;
  return po33_pattern_fx_encode(&fx, pattern->footer_raw,
                                sizeof(pattern->footer_raw));
}
```

Then use `po33_pattern_encode` to serialize the edited logical record. The
existing packed fields remain available; the new views do not alter struct
layout or require allocation.

Pattern event words remain raw. In the descriptive q0–q3 partition, q0 has an
observed pitch role and q1 an observed level role; q2 controls a filter-like
response, with cutoff a strong inference. q3's resonance interpretation remains
an unconfirmed candidate. Exact scales, field widths, zero/sentinel behavior
and playback state carry are unresolved. Preserve parameter-only rows with
zero control bytes. See [PO-33 format reference](../formats/PO33.md) for the field map and
the distinction between observed behavior and candidate meanings.

`po33_sample_decode` expands one signed-order mu-law byte to PCM16.
`po33_sample_encode` selects the nearest representable level, with ties toward
zero. The nominal sample clock is 23,437.5 Hz. Headers and full allocated pools
must be handled by the application; the sample codec does not apply trims or
resolve slice references. Resolve a source selector against the whole stored
pool, not its owner's trimmed interval. Raw range endpoints can overlap or
exceed an allocation; endpoint inclusion and the cause of those anomalous
ranges remain unresolved. Do not clamp, wrap or rescale them on decode.

`po33_sample_count_for_pcm(count, rate, &required)` sizes a bulk conversion from
finite normalized mono PCM at 8,000–192,000 Hz. Except for the native WAV alias
23,438 Hz, the output count is `ceil(count * 46875 / (2 * rate))`, targeting the
nominal 23,437.5 Hz clock. The alias keeps the input count unchanged.

`po33_samples_encode_f32(pcm, count, rate, output, capacity, &written)` performs
bandlimited sample-rate conversion and emits one mu-law byte per output sample.
For example, one second at 48 kHz needs 23,438 output bytes. Input samples must
be finite and in `[-1,1]`; invalid samples are rejected before any output writes.
Resampling overshoot is saturated before PCM quantization. No input gain
normalization is performed.

Both functions set their output count to zero on error. Empty input produces
zero samples; input and output buffers may be null when their required lengths
are zero. Buffers and count storage must not overlap. The caller supplies memory;
there is no heap allocation, libc or libm dependency. The bulk API creates only
sample bytes, leaving block padding, headers and template edits to the caller.
